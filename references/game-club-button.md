# 微信游戏圈按钮接入

在修改项目前，先核对微信小游戏当前官方文档中游戏圈按钮接口、基础库要求和参数。优先使用官方原生游戏圈按钮能力，例如当前文档仍支持时使用 `wx.createGameClubButton`；不要猜测页面 URL，也不要用普通跳转接口伪造游戏圈入口。

## 1. 定位首页和坐标系统

1. 识别 Creator 2.x 或 3.x、首页场景和控制首页显示的组件。
2. 记录设计分辨率、Canvas 适配模式、横竖屏、微信安全区域、右上角胶囊区域和首页已有按钮的实际边界。
3. 选择首页边缘的空闲位置，保持与相邻控件一致的间距。不得遮挡开始游戏、关卡、商店、签到、设置、广告、导航栏、系统胶囊或其他主要交互区域。
4. 原生微信按钮使用屏幕像素坐标时，将 Cocos 设计坐标按真实窗口尺寸、Canvas 缩放和安全区域转换后再设置；不要把编辑器中的节点坐标直接当作屏幕像素。

若多个位置都可用，优先选择用户拇指容易触达、视觉层级低于“开始游戏”且不会造成误触的位置。没有可靠空位时，先调整次要装饰或非关键控件布局，不得覆盖核心 UI。

## 2. 制作按钮图片

- 图片应与游戏主题、色彩、描边、光影和按钮形状一致，清晰表达“游戏圈/社区”入口，不使用与项目无关的品牌元素。
- 使用微信接口支持的 PNG、JPG 或 JPEG；需要不规则轮廓时优先透明 PNG。
- 最终只保留项目实际引用的成品资源。导出后运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check-game-club-asset.ps1 -Path '<按钮图片绝对路径>'
```

- `withinLimit` 必须为 `true`，即文件大小不超过 `50 * 1024` 字节。超限时优先压缩调色板、移除无用元数据和按显示尺寸缩放；不能以明显模糊为代价硬压缩。

## 3. 接入官方能力

1. 仅在微信小游戏环境执行，先检查 `wx`、目标接口和所需基础库能力是否存在。
2. 按当前官方文档创建图片类型的游戏圈按钮，并传入成品资源与屏幕像素样式。按钮必须打开当前 AppID 对应的微信官方游戏圈。
3. 全局只保留一个实例。首页显示时创建或 `show`；离开首页、进入关卡或弹出会冲突的全屏界面时 `hide`，不再需要时 `destroy` 并清空引用。
4. 处理首页重复进入、前后台切换、窗口尺寸变化和场景销毁，避免重复按钮、悬浮残留或坐标漂移。
5. 非微信环境或接口不支持时安全跳过，不阻断首页加载，不用虚假按钮冒充已接入成功。

接口名称、参数和基础库要求可能更新。实现时以微信小游戏官方文档为准；若项目 AppID 尚未开通游戏圈能力，记录后台需要完成的配置并停止宣称该功能已验收。

## 4. 验收门禁

完成前逐项验证：

- 成品图片实际字节数不超过 50 KB，构建后资源路径有效。
- 常见长宽比、刘海屏和全面屏上都位于安全区域，且不遮挡、挤压或误触原有 UI。
- 首页首次进入和多次返回时只出现一个按钮；离开首页后按设计隐藏或销毁。
- 微信开发者工具无相关报错，真机点击后打开当前 AppID 的官方游戏圈，而不是网页、其他小程序或其他游戏入口。
- 前后台切换、场景切换、分包加载和构建后混淆不会破坏按钮。

开发者工具预览不能代替真机点击验收。真机未验证或 AppID 后台能力未开通时，在最终报告中明确标记为未完成，禁止把开发版本描述为已全部验收。
